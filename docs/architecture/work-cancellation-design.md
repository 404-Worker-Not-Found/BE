# 확정 근무 취소·노쇼 설계 초안 (#104)

상태: 정책 답변 대기. 아래 제안은 확정 결정이나 현재 구현 사실이 아니다. 이 문서는 구현 전에 검토할 범위와 질문을 정리한다.

## 현재 구현과 제약

- 확정된 근무의 참여자 조회, GPS 출근, 점주 시작·완료, 상태 이력과 Outbox는 구현되어 있다.
- 기존 `Work.cancel()`과 내부 취소 API는 매칭 확정 전 Saga 보상 전용이다. 확정 근무에 재사용하지 않는다.
- job-service의 예약 해제는 `RESERVED`에만 허용되고 `CONSUMED`는 거절한다. 확정 취소로 자리를 반환하려면 별도 계약이 필요하다.
- matching-service의 기존 취소 처리는 `PENDING` 제안용이다. 확정 근무 종료를 전파하는 경로는 없다.
- payment-service에는 매칭 잠금 해제가 있지만 PG 환불과는 다르다. PG 환불은 #107의 별도 명령이며 실제 토스 취소 검증 후 호출자 연결이라는 선행 조건이 있다.
- 근무 이벤트는 `work:domain-events`에 저장하며 notification-service는 현재 출근·시작·완료만 소비한다.
- 근무 이벤트 revision은 현재 상태에 따라 1·2·3으로 고정된다. 취소·노쇼를 추가할 때 기존 이벤트의 revision·payload 해석을 깨뜨리지 않아야 한다.

## 우선 결정할 제품 정책

| 항목 | 제안 | 상태 |
| --- | --- | --- |
| 참여자 취소 | 점주·알바생이 사유를 입력하고, 확정된 SCHEDULED이며 출근 전·예정 시작 전이면 취소 허용 | 질문 발송, 미정 |
| 노쇼 판정 | 기존 출근 허용 시간의 종료 경계는 출근에 포함하고, 그 이후에도 미출근인 확정 SCHEDULED를 자동 판정 | 질문 발송, 미정 |
| 패널티 | 취소 주체·사유·노쇼 사실을 기록하고 알림부터 제공. 금전 벌금·신뢰점수 차감은 수치가 정해질 때까지 보류 | 질문 발송, 미정 |

아래 항목도 구현 범위를 확정하기 전에 확인한다.

- 취소·노쇼로 비게 된 자리를 다시 모집할지, 기존 공고를 닫힌 상태로 유지할지. 자동 재모집·후보 폴백까지 포함하면 #104의 계약 범위가 커진다.
- 노쇼 이의 제기와 GPS·서비스 장애 예외를 누구에게 어떤 경로로 접수할지. 이 정책 없이 노쇼를 되돌리거나 정산·환불을 자동 재실행하지 않는다.
- 지급·환불 금액이 귀책에 따라 달라진다면 #105·#107의 확정 전이와 함께 별도 합의한다. ‘패널티 보류’만으로 지급·환불 금액이 결정되는 것은 아니다.

## 서비스 책임과 연결 방향

| 서비스 | 책임 |
| --- | --- |
| work-service | 근무 취소·노쇼의 원본 상태, 참여자 권한·시간 판단, 행위자·사유 이력과 이벤트 |
| matching-service | 확정 매칭·선정 지원의 종료 반영. 기존 미확정 Saga 보상을 재실행하지 않음 |
| job-service | 확정 자리의 종료 기록·모집 인원 반영과 재모집 여부. 정책 확정 후 별도 내부 계약 |
| payment-service | 종료 사실에 대응하는 잠금·정산·환불 상태 및 금액 안전성. 타 서비스 DB 직접 접근 금지 |
| notification-service | 참여자 알림, 중복 이벤트 방지 |
| member-service | 추후 확정된 신뢰도·패널티 정책 적용 |
| chat-service | 추후 시스템 메시지·종료 후 채팅 정책 적용 |

## 근무 명령의 구현 방향

- 참여자용 취소 API를 기존 Saga 보상 API와 분리한다. API 경로는 기존 `/api/works/me/{workId}` 체계에 맞춘다.
- 현재 참여자 확인 방식으로 본인 근무·역할을 검증하고 work 행을 잠근 뒤 상태와 현재 시각을 다시 판단한다. 다른 회원과 미확정 근무는 기존처럼 404로 숨긴다.
- 취소·노쇼 판정과 행위자·사유 이력, Outbox 이벤트를 같은 로컬 트랜잭션에 저장한다.
- 같은 종료의 재요청은 원래 처리 결과를 유지한다. 다른 종료 상태를 덮어쓰거나 사유를 바꾸지 않는다. 구체적인 멱등 키·충돌 응답은 API 설계에서 명시한다.
- 현재 시간은 근무 일정 시간대 Clock을 사용하고 DB 저장 정밀도로 맞춘다.
- 출근 허용 종료 순간에는 출근을 허용하며 노쇼는 그 이후에만 가능하게 경계를 일치시킨다.
- 자동 판정 작업은 후보 조회 후 각 근무를 짧은 트랜잭션으로 잠가 재검증한다. custom 출근 정책의 경우 노쇼 기한도 같은 정책에서 제공하도록 계약을 정한다.
- 노쇼의 시스템 행위자는 회원 ID를 꾸며 쓰지 않는다. 이력의 actor/command 제약과 이벤트 소비자의 역할 검증을 함께 확장한다.

## 후속 처리와 복구

- 종료 이벤트의 eventId로 소비 중복을 제거하며, 결과가 영속화된 뒤 ACK한다. 관련 없는 이벤트와 해석 불가 이벤트는 기존 규칙을 따른다.
- 확정 자리 반환·매칭 종료·결제 잠금 해제는 각각 안정적인 업무 식별자와 명령 키로 재요청할 수 있게 한다.
- 원격 결과 미확정은 같은 명령으로 조회·재시도한다. 네트워크 장애만으로 새 취소·환불 명령을 만들지 않는다.
- 잠금 해제 성공을 PG 환불 완료로 표시하지 않는다. 완료된 정산이나 미확정 지급·환불을 임의로 되돌리지 않는다.
- 종료 사실과 금액 후속 처리를 구분해 조회할 수 있게 한다. 금액 처리가 끝나지 않았으면 기존 회원 탈퇴 차단을 유지한다.
- 취소·노쇼 이벤트가 MatchConfirmed보다 먼저 도착하는 순서 역전도 고려한다. 선행 자료가 없으면 유실시키지 않고 pending으로 재처리한다.

## 검증 계획

- 권한, 미확정 근무, 취소 사유 검증, 시작 시각 직전·동일·직후, 출근 마감 경계.
- 동시 양측 취소, 취소와 출근·시작 경합, 노쇼와 출근·참여자 취소 경합.
- 재요청에서 최초 행위자·사유·처리 시각 유지 및 중복 이력·Outbox 방지.
- 이력·Outbox 저장 실패의 상태 롤백.
- 같은 이벤트 재전달, DB 커밋 뒤 ACK 유실, 이벤트 순서 역전, 재시작·Redis 장애 복구.
- 예약/확정 자리 구분, 대체 근무에 대한 늦은 종료 명령, 모집 인원 불변식.
- 잠금·정산·환불 경합에서 금액 보존과 미확정 결과의 재사용 방지.
- notification 중복 방지와 시스템 행위자 호환성.
- 서비스 간 계약 변경이 포함되므로 전체 `./docs/scripts/verify.sh`와 해당 서비스의 MySQL/Redis 통합 테스트.
