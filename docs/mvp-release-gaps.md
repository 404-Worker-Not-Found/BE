# MVP 이후 출시 보강 목록

이 문서는 MVP에서 의도적으로 제외하거나 제한한 동작을 추적한다. 실제 금전 지급·환불이나 법적 의무가 완료됐다는 의미로 사용하지 않는다.

| 영역 | MVP 기준 | 출시 전 필요한 보강 |
| --- | --- | --- |
| 취소·노쇼 | 양측 동의 취소, 기한 경합 방지, 자동 노쇼 사실·알림, 패널티 없음 | 이의 제기·GPS/서비스 장애 예외, 운영자 권한·감사 이력, 귀책별 금액·신뢰도 정책 |
| 종료 전파 | 신뢰할 수 있는 근무 이벤트와 매칭·결제 소유 데이터 대조, 수신 기록·멱등 처리 | 지속 실패 탐지·운영 재처리 화면, 소비자 인스턴스/보존·장애 대응 운영 기준 |
| 결제 잠금 | 정상 예치의 취소/노쇼 잠금을 전액 가용 잔액으로 복귀; 차단/정산 이관은 검토 대상 | 차단 예치 복구(#108), 외부 취소 대사, 모순된 종료·정산의 운영 판단·복구 |
| 환불 | 잠금 해제와 실제 PG 환불을 구분 | 실제 토스 부분/전체 환불·웹훅 검증 후 호출자 연결, 미사용 예치 자동 환불 기준 |
| 지급 | 자동테스트의 지급 대역으로 명령·재시도 검증; 실제 서버의 미연동 지급은 대기 유지 | 개인 수취인 본인인증/KYC·토스 계약, 계좌 소유권·암호화·변경 통제, 실환경 대사·지급 검증 |
| 수수료·공제 | 기존 잠금 전액을 정산 예약. 테스트에서만 같은 금액으로 검증 | 부담 주체·수수료·세무/원천징수 정책을 확인하기 전 실제 지급하지 않음 |
| 모집 | 취소 뒤 기존 공고를 자동 재오픈하거나 폴백하지 않음 | 확정 자리 반환·동시 재모집·가격/예치·남은 시간 정책 및 계약 |
| 알림·채팅 | 인앱 보관함과 REST 재조회 | 실시간/외부 푸시, 종료 시스템 메시지·채팅 보관 정책 |
| 사업장 소유권 | 공고 생성 시 활성 점주의 등록 프로필 ID를 실제 member-service 조회로 대조 | 기존 임의 businessId 데이터 점검·법적 대표자 확인·여러 사업장/양도 정책 |
| 개인정보 | 기존 계정 장벽·조회 권한 유지; 취소 사유 전문을 이벤트/알림에 포함하지 않음 | 추가 이력의 보존·삭제 기간, 운영자 접근 제한·감사, 개인정보 파기 자동화 |

실제 금융 결과가 미확정이면 성공으로 만들거나 새 키로 중복 실행하지 않는다. 출시 보강 항목은 테스트 대역의 성공으로 완료 표시하지 않는다.
